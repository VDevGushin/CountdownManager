# Countdown Manager v1.2.2

Нативное приложение для строки меню macOS 13+, SwiftUI + AppKit, без сторонних зависимостей. Собранная версия предназначена для Apple Silicon; исходники можно собрать на Intel Mac.

## Управление проектом через ИИ

Проект рассчитан на модель, где владелец управляет продуктом и описывает задачи обычным языком, а ИИ берёт на себя архитектуру, код, тестирование, документацию и проверку сборки. Правила для агента находятся в [`AGENTS.md`](AGENTS.md), подробный рабочий процесс — в [`AI_WORKFLOW.md`](AI_WORKFLOW.md).

## Запуск

Откройте **Countdown Manager.app**. В строке меню появится **◷ Countdown**. Нажмите на него и добавьте первый счётчик. Иконки в Dock нет.

Для постоянного использования перенесите приложение в «Программы», запустите оттуда и включите «Запускать при входе в macOS». Если macOS запрашивает разрешение, в меню появится кнопка перехода в системные настройки. Автозапуск по умолчанию выключен.

## Возможности

- Любое количество счётчиков: название, небольшая необязательная заметка, будущая дата, один emoji, основной.
- Сегодняшние и прошлые даты запрещены в выборе и при сохранении.
- Основной счётчик показывается как `☀️ 238 дней`; первый автоматически становится основным.
- Звезда назначает основной счётчик; выбранная карточка плавно перемещается наверх и подсвечивается. Меню `…` позволяет редактировать или удалить.
- Перед удалением приложение запрашивает подтверждение.
- При удалении или наступлении даты основного выбирается ближайший оставшийся.
- В дату события оно весь день показывается как `Сегодня`. Прошедшие события удаляются следующей ночью, без архива. Проверка выполняется в полночь, после пробуждения, изменения часов/часового пояса, открытия меню и дополнительно каждые 30 секунд.
- «Приложение» → перезапуск или выход.

Дни считаются по календарю, не делением секунд на 86400. Даты сохраняются как год/месяц/день. Файл данных: `~/Library/Application Support/CountdownManager/countdowns.json`; запись атомарная. При ошибке чтения файл не перезаписывается. Синхронизации, повторов и отсчёта после даты нет.

В локальную полночь значение каждого счётчика уменьшается на день. Когда наступает дата события, в карточке и строке меню появляется `Сегодня`; событие удаляется только после завершения этого дня.

Чтение, JSON-кодирование и запись выполняются вне главного потока, поэтому работа с файлом не блокирует интерфейс. Последовательное хранилище и номера ревизий защищают от перезаписи нового состояния запоздавшей операцией. Поля даты проверяются при чтении; некорректный календарный день считается ошибкой файла, а не исправляется автоматически.

## Диагностика

Приложение ведёт локальный журнал действий и ошибок, не записывая названия событий, заметки или emoji:

`~/Library/Application Support/CountdownManager/Logs/countdown.log`

Когда файл достигает 512 КБ, предыдущая часть сохраняется как `countdown.previous.log`. Журнал содержит запуск и завершение приложения, открытие формы, результат сохранения, изменение основного счётчика, ошибки чтения/записи и обнаруженные зависания интерфейса. Если главный поток не отвечает 5 секунд, фоновый сторож добавляет `ui.stall detected`; после восстановления — `ui.stall recovered`.

Для разбора проблемы сохраните оба файла журнала до следующего длительного использования приложения. Пользовательские названия, заметки и emoji в журнал не попадают.
Папку можно открыть из меню **«Приложение» → «Открыть папку диагностики…»**.

## Сборка

Нужны Apple Command Line Tools (`xcode-select --install`) или Xcode.

```sh
./build.sh
swift run CoreChecks
swift run UIChecks
```

`Package.swift` также открывается в Xcode. Скрипт создаёт `.app` и подписывает локальной ad-hoc подписью. Для распространения на другие Mac нужны Developer ID и нотарификация Apple.

Unit-проверки покрывают даты, CRUD, заметки и их границы, выбор и замену основного, жизненный цикл события в день наступления, JSON, переходы лет/летнего времени, високосный день и склонения. UI state-проверки используют тот же слой представления, что и SwiftUI: проверяют заметку, подпись «Сегодня», допустимость формы, перестановку и сохранение нового основного события на отдельном временном хранилище.

На машине разработки установлен только Apple Command Line Tools без полного Xcode, поэтому системные XCUITest здесь недоступны. `UIChecks` детерминированно проверяет состояния, которые использует SwiftUI, но не запускает системное accessibility-дерево и не измеряет покадровую плавность анимации. Эти визуальные аспекты проверяются вручную на установленном приложении.

Нативные API: [NSStatusBar](https://developer.apple.com/documentation/appkit/nsstatusbar), [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp).
