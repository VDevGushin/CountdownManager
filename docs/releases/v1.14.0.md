# Countdown Manager 1.14.0 / build 28

Статус: **проверенный подписанный выпуск подготовлен, ещё не опубликован**.
Предыдущий опубликованный выпуск — [1.13.5 / build 27](v1.13.5.md).

## Изменения

Событие сохраняет режим названия: автоматическое по выбранной дате либо своё.
Новый день начинается с названия дня недели; перенос даты обновляет его и после
сохранения, повторного открытия и перезапуска. Обычный `+` начинает пустое своё название.
Ручное изменение переключает черновик на своё название. Действие **«Название по дате»**
сразу возвращает название выбранного дня и автоматический режим в черновике.

Дата, название и режим записываются вместе только после успешного Save. Cancel
сохраняет исходное событие; ошибка записи оставляет черновик для повторной попытки.
Undo текста не включает автоматический режим. Заметка, emoji, задачи, погода и избранное
от смены режима не меняются. Автоматическое название не переносит событие на следующий день.

**Старые события остаются со своими названиями**, даже если называются «Четверг».
Для включения нового поведения откройте событие и нажмите «Название по дате», затем Save.
Сброса данных и распознавания дней по тексту нет. Новый optional JSON boolean
`usesAutomaticTitle` по умолчанию false; обычное поле title сохранено для старых читателей.

## Аудит покрытия перед выпуском

| Правило | Проверки |
| --- | --- |
| Legacy, true/false, неверный тип/null, совместимость JSON | Core `AutomaticTitleChecks` |
| Все дни недели, год, високосный день и civil даты DST | Core canonical Save tables |
| Auto не обходит ограничения заметки, emoji и задач | Core пять отрицательных non-title inputs, неизменность snapshot |
| Пустой/пробельный title → reset, но не обход invalid note/task | Пять directed UI-state вариантов reset |

| Конкурирующие записи | Восемь success/failure/completion-order исходов с согласованным mode/date/title/favorite |
| Циклические пользовательские действия | Четыре fixed seeds × 192 шага = 768, независимый oracle после каждого шага |
| Настоящий текстовый ввод и Undo | Пять внешних XCU-сценариев; русский layout-aware Undo, exact title/mode |

Блокирующих production-дефектов аудит не обнаружил. Найденные небольшие пробелы в прямых
assertions закрыты до итогового запуска. Это покрытие классов поведения, а не обещание
перебрать каждый возможный ввод пользователя.

Strict SwiftLint: **0 нарушений**. CoreChecks/UIChecks с дополнениями — PASS.
Отдельно прошли **32** проверки eval runner и **12** проверок release tooling.
Первый dev UI-прогон потерял фокус при внешнем переключении окна; этот результат не принят.
Полная UI-матрица повторена на **точном production-пакете 1.14.0/28**: общий smoke,
collapse, editor, три continuity-прогона и capture — **7 успешных запусков**.

Пять внешних сценариев редактора переиспользованы с неизменными production-источниками:
три row/mode-cycle сценария и два layout-aware edit/Undo. Односимвольный `x` не доставлялся
XCU-драйвером и на исходном main `2933a22`; это не регрессия функции. Тесты не меняют
раскладку пользователя. Границы исследования записаны в [VERIFICATION](../VERIFICATION.md).

## Ограничения

arm64, ad-hoc, без Apple notarization. Старые macOS, Intel, Gatekeeper first install,
внешний ввод даты, IME, особые Command-раскладки, VoiceOver speech и реальные Spaces
в этой приёмке не воспроизводились. Полный Sparkle download/replace/relaunch не повторялся;
проверены сохранённая конфигурация и криптографические подписи.
Отдельного native теста удержанной записи с нажатием reset нет: новая кнопка наследует
`.disabled(isSaving)` от формы. Production-данные не использованы как fixtures.
