## Change

Fresh macOS screenshot thumbnails can be dropped onto an event and received as local image
attachments. The receiver loads an advertised encoded image as a file, makes its own temporary
copy inside the provider callback, and retains it through the existing Store/editor import.
File URLs keep priority; image-only alternatives prefer PNG/TIFF. Names and encoded bytes are
preserved without application-side decoding or re-encoding. Unsupported representations no longer
fall through to an unadvertised public.plain-text request.

The provider request arbitrates exactly-once completion, including cancellation followed by late
success or error callbacks. Durable storage, the 15-file limit and draft Save/Cancel remain unchanged.
The Xcode target now registers the existing DesktopSheetTerminationPolicy.swift so its external
verification path builds without a temporary project workaround.

## Functional acceptance before packaging

Strict SwiftLint, CoreChecks and UIChecks passed on the feature source, including byte preservation,
names and extension aliases, lossless priority, temporary-file lifetime/cleanup, unsupported formats,
durability, draft Cancel, overflowing batches and cancelled delayed providers.

The native materials scenario passed 1/1. The real external Finder PNG test passed 1/1, checking an
unselected receiving event, original filename and bytes, source-file preservation and app restart.
The owner confirmed actual floating-thumbnail intake in an isolated native desktop tester;
eight PNGs across two test events passed structural, chunk-CRC, dimension and size checks.
This manual tester preceded the release-version/help change and is not labelled the final ZIP.

The screenshot-thumbnail XCUITest stopped before dragging because screencaptureui exposed no
accessible thumbnail window. It was not retained as a flaky regression. Every mini/editor drop
target was not independently observed; general Mail/Photos file promises are not advertised.
