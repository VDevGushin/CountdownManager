## Evidence and safety rules

- `A` means an existing automated assertion is mapped below; its latest actual result/provenance must be attached by the executing agent. `A-partial` means only a lower layer or a subset of the scenario is covered. `M` means an actual external/manual interaction remains necessary. `GAP` is a meaningful missing composition, not proof of a product defect.
- Core/UI helper checks, direct SwiftUI registry actions, in-process AppKit APIs and property checks are not external keyboard, Dock, Spaces, physical status-item or VoiceOver PASS. The desktop smoke enables production lifecycle callbacks; general smoke and XCUITest suppress several shell lifecycle callbacks. Both still have those external boundaries.
- Run GUI surfaces serially. Never use installed production event files, normal preferences, real login registration, global Mission Control settings or production update keys as fixtures. Use marked isolated homes and synthetic weather. Native permission/network, power assertion and signed-updater tests are separate deliberate surfaces, not incidental side effects of routine regression.
- Keep failed/interrupted/driver-limited runs separate from successful evidence. Record build SHA, SDK/runtime/architecture, test count and result file. Screenshots prove only visible layout states. The 500 ms desktop handoff stability assertion proves only the bounded observation interval.
- Reuse valid evidence only if subject sources/configuration/binary still match. Fresh Store/repository/defaults objects are not process-relaunch proof. A retained test app can be moved; provenance must identify its actual location rather than a nonexistent copy beside PNGs.
