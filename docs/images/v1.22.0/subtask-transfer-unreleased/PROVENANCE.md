# Перенос подзадач — нативная проверка разработки

[Итоговая приёмка после исправлений](RELEASE_READINESS.md) содержит финальный пакет,
прогон 14/14, актуальные изображения и ограничения внешнего драйвера. Остальные разделы
этого файла сохраняют историю первоначальных проверок.

Проверено 16 ноября 2026 года в ветке `codex/subtask-transfer`, поверх `8d0a49ae67b317cad10e3329ac1641a5a02e102a`.
Это рабочая версия на базе 1.22.0/44. Снимки показывают реализованную функцию на
изолированных демонстрационных данных. Публичный пакет 1.22.0 описан в
[историческом протоколе](../PROVENANCE.md).

## Сборка и изображения

Исполняемый файл SHA-256 `df7be424e0b248225b5b02fe6f33f1ffd6166cb78d58f7b9f7df904ae2f6b285`.
Компилятор использовал SDK 27.2,
целевой macOS 13.0 и принятую linked compatibility 13.0.
Оформление `native-calendar-graphite-v2` проверено штатным build contract.
[Manifest](manifest.json) хранит происхождение каждого PNG и параметры среды.
[Хэши исходников](source-sha256.json) идентифицируют проверенные Swift-файлы и маршрут запуска.

Получено десять нативных PNG — мини-панель со стрелками, inline-форма мини-панели
и большого окна, Light/Dark и оба варианта Increase Contrast для форм.
Проверены размеры, подписи, положение стрелок справа и доступность элементов формы.
Метод снимков `NSView.cacheDisplay` подтверждает рисование нативного содержимого.

## Автоматические проверки

- Полный SwiftLint — 0 нарушений.
- `./verify.sh fast` — PASS, [журнал](fast.log).
- `./verify.sh subtask-transfer-capture` — PASS, [результат](ui-smoke-result.txt).
- Core/Store проверяют неизменность соседних данных, сохранение UUID и порядка,
  предел 10, старые данные с совпадающими UUID, истечение источника, отказ записи,
  повтор, перезапуск, конкурирующую запись и смену дня во время сохранения.
- Нативный сценарий проверяет отдельные стрелки, inline-форму, Cancel, скрытие/возврат,
  общий владелец редактирования, выбор из нескольких получателей, полный получатель,
  перенос выбранного пункта, создание дня и повтор после искусственного отказа записи.

Дата и получатель в автоматическом нативном сценарии изменяются через API сеанса.
Стрелка, отмена и подтверждение используют production-обработчики кнопок.
Первая попытка нативного сценария выявила устаревшее замыкание в регистрации новых
тестовых кнопок. Маршрут `subtask.transfer.*` переведён на существующую нативную
регистрацию, обновляющую обработчик при изменении формы. Успешный набор выше получен
после этого исправления.

## Проверка через обычный интерфейс

На отдельном marked-профиле обычными нативными контролами выполнены следующие действия.

- В большом окне стрелка открывает форму, native menu выбирает «Вторник», кнопка
  переносит «Отправить документы». Проверены получатель и исходный UUID в JSON.
- Native date field принимает 18.11.2026, Escape отменяет форму.
- В мини-панели native date field принимает 18.11.2026, форма предлагает создание дня,
  подтверждение создаёт «Среда» с «Записаться на сервис».
- Выполненная «Заказать продукты» остаётся у источника.
- Возврат через существующее действие «К переносу» открывает сохранённую mini-форму.

Эти действия проверены на предыдущем тестовом пакете с той же реализацией функции.
От окончательного пакета он отличается только регистрацией smoke-обработчиков,
которая выключена в manual visual preview. Последний пакет отдельно прошёл
автоматический нативный сценарий.

Реальные Spaces, VoiceOver, все варианты клавиатурной навигации и compositor timing
в этом точечном прогоне не проверялись. Reduce Motion включён для стабильных снимков.
Тестовое окно использует 1200-point content width, минимальная ширина desktop-панели
с длинным названием получателя отдельно не проверялась.

## Расширенный ручной QA

По запросу владельца 16 ноября выполнен отдельный внешний прогон через обычные
нативные кнопки, меню, поля и клавиатуру. [Матрица и фактические результаты](manual-qa.md)
содержат 28 прошедших сценариев, включая реальный отказ записи только в синтетическом
профиле и повтор после восстановления прав. Сохранность и ожидаемое размещение всех
38 исходных подзадач проверены по итоговому JSON. Узкое большое окно и длинный
получатель проверены при наблюдаемой ширине 960 pt. Полные границы этого прогона
зафиксированы в отдельном отчёте.
