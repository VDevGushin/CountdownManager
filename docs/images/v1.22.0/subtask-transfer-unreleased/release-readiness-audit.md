# Аудит готовности переноса подзадач к выпуску

[Итоговая сводка после завершения исправлений и нативного прогона](RELEASE_READINESS.md)
фиксирует актуальную сборку. Ниже сохранены этапы аудита и их первоначальная хронология.

Проверено 16 ноября 2026 года без запуска приложения и изменения фокуса.
Обновлено после дополнительных результатов основного агента и исправления Store race.
Область аудита охватывает происхождение проверенного кандидата, соответствие документации,
релизный маршрут, публичную текущую версию и релевантность регрессионных проверок.

## Итог

Первичный read-only аудит подтвердил исходный development-кандидат на базе 1.22.0/44.
Последующая расширенная проверка воспроизвела Store race при очереди полного сохранения события
за выполняющимся переносом. Узкое исправление внесено, новые регрессионные сценарии прошли
в окончательном `verify.sh fast`. Дополнительно исправлены пропущенные ссылки трёх новых
Swift-файлов в явном Xcode source list. Фактический `build-for-testing` завершился успешно.
[Фоновый fast-журнал](readiness-fast.log) и [журнал Xcode](readiness-xcode-build.log) сохранены отдельно.

Прошедшие нативные и 28 внешних ручных сценариев относятся к исходному кандидату
`df7be424…`. Они сохраняют свои фактические результаты для того пакета. Отдельный новый кандидат
после hardening собран с SHA-256 `b94af3e80eb384741099d3bf3aec3739151c7a7359d22eda42866b96906576f8`.
Его фоновые проверки прошли, затронутая нативная/внешняя приёмка остаётся ожидающей фокуса.
Новый выпуск требует обычной подготовки версии, release-help, release-configured пакета и
подписанного канала после отдельного решения владельца о выпуске. Отсутствие этих будущих
артефактов на стадии проверки функции соответствует текущему процессу.

Дополнительные внешние проверки, требующие активации окон или изменения фокуса, отложены
по текущему ограничению владельца. Они остаются отдельной частью общей приёмки основного
агента. Этот аудит их не запускает и не подменяет предположением о результате.

## Находки расширенного readiness-аудита

### Store race за выполняющимся переносом

Основной агент воспроизвёл последовательность, где `Store.save` получает полный снимок
source или recipient до завершения transfer, ждёт существующий барьер, затем сохраняет
устаревшее содержимое. Source-снимок мог вернуть уже перенесённый UUID, recipient-снимок мог
стереть поступивший пункт. Обычный UI закрывает этот путь editing guards, однако Store mutation
boundary должна сохранять согласованность при таком программном пересечении действий.

Внесённая защита сравнивает same-ID event до и после ожидания только у save, действительно
начавшегося во время transfer. При изменении этого события save выдаёт ясный конфликт и не
выполняет лишнюю запись. Unrelated same-date event сохраняется обычным образом. После failed
transfer исходное событие не меняется и его queued save разрешён. Обычные overlapping saves
сохраняют прежний контракт. Новые controlled-continuation регрессии покрывают source, recipient,
unrelated и failed-source варианты, полное durable состояние и единственность moved UUID.
Все четыре controlled-writer проверки прошли в окончательном fast-прогоне. Точный воспроизводитель
после исправления даёт один экземпляр UUID и одну запись переноса при отклонённом stale save.

### Явный Xcode source list

В `CountdownManager.xcodeproj/project.pbxproj` отсутствовали три добавленных файла
`SubtaskTransfer.swift`, `SubtaskTransferView.swift` и `SubtaskTransferSmokeScenario.swift`.
SwiftPM-сборка включала их автоматически и могла оставаться green при неполном Xcode-маршруте.
Агент добавил project references и проверку согласованности source list. Все 19 contract-проверок
и 7 design-проверок прошли. In-memory mutation probes отвергли отсутствующий file reference,
отсутствующий Sources entry и неверный target. Фактический Xcode `build-for-testing` прошёл с кодом 0.
Это предмет исправления build route, отдельно от обычной подготовки следующего номера версии.

## Релевантность регрессий

Прочитаны тела `SubtaskTransferChecks.swift`, `SubtaskTransferWorkflowChecks.swift`, transfer-проверки
в `DesktopWindowChecks.swift`, текущий native scenario, [fast-журнал](fast.log),
[native-результат](ui-smoke-result.txt) и [28 внешних ручных сценариев](manual-qa.md).

| Изменённый риск | Наблюдаемое условие проверки | Граница доказательства |
| --- | --- | --- |
| Удаление неверного пункта, потеря UUID/порядка/метаданных | Core сравнивает полные source/target/neighbor, favorite и JSON round-trip. Отказы сравнивают весь исходный snapshot | Проверяет модель и сериализацию |
| Полный получатель, повтор, старые совпадающие UUID | Core отклоняет 10, разрешает 9→10, повторно переносит уже отсутствующий source UUID и проверяет collision | Проверяет валидацию без зависимости от UI disabled-state |
| Частичная запись, потеря при отказе или перезапуске | Store writer получает единый кандидат. При ошибке старый JSON побайтово сохранён, retry и новый Repository читают ожидаемое полное состояние | Проверяет durable boundary |
| Исчезновение source во время записи, конкурирующая мутация и полночь | Controlled continuations удерживают запись. Source snapshot остаётся опубликованным, повтор отклоняется, favorite ждёт, normalization применяется после durable transfer | Детерминированная асинхронная последовательность без оценки визуального транзиента |
| Устаревший full-event save ждёт transfer | Добавлены четыре controlled-continuation варианта. Они требуют одного transfer write для отклонённого stale save и разрешают unrelated/failed-source save | Новые регрессии прошли в fast; UI-приёмка нового кандидата ожидает доступного фокуса |
| Форма потеряла владельца или допускает stale callback | Session-тесты отклоняют чужой/stale draft, удерживают saving reservation, освобождают её после результата, сверяют reconcile исчезнувшего/выполненного source | Проверяет session API, без внешней доставки клавиш |
| Стрелка/форма отличаются между поверхностями | Native scenario вызывает production actions, проверяет Cancel bytes, full target, перенос и retry. Сохраняет 10 Light/Dark/contrast PNG | Target/date меняются через session API. Изображения получены через `NSView.cacheDisplay` |
| Обычное native menu/date input, отдельные hit targets и пользовательский workflow | Внешний manual QA использует CUA кнопки, меню, AX поля и клавиатуру, реальные права синтетического каталога и итоговый JSON всех 38 UUID | Границы внешнего прогона перечислены в manual-qa |

Существующие green Core/UI suites не приравниваются к проверке каждого пользовательского
взаимодействия. Указанные три слоя дополняют друг друга. VoiceOver speech, реальные смены Spaces,
все focus-navigation варианты, точный минимальный resize clamp и полный compositor/transient timing
остаются вне сохранённых свидетельств. Их остаточный риск учитывается в общей приёмке.

## Оставшиеся шаги процесса выпуска

Фоновые проверки исправлений Store race и Xcode source list прошли. Следующие действия
охватывают сборку нового кандидата, его нативную приёмку и обычную release preparation.

1. Выполнить для отдельного post-hardening candidate выбранную основным агентом затронутую нативную/внешнюю
   приёмку после снятия ограничения на фокус. Записать новую точную идентичность кандидата,
   сохранив исходные native/manual receipts привязанными к `df7be424…`.
2. По отдельному решению о выпуске согласовать новую версию/build, обновить release-help и
   release notes, текущие ссылки/описания и candidate-изображения. Исторические evidence сохраняются.
3. По разрешённому Git workflow интегрировать проверенную функцию и относящиеся к ней материалы
   в актуальную `main`, отдельно разобрав сохранённые параллельные изменения skills.
4. Зафиксировать окончательный source, собрать production-configured пакет, проверить embedded key
   и feed, подпись ZIP/feed, altered-input rejection, extraction bytes/modes/symlinks и strict/deep
   codesign. Изменившийся executable требует соответствующих exact-package свидетельств.
5. Публикация, аннотированный тег, отправка Git-изменений и установка остаются отдельными действиями
   по полномочиям текущего чата. После публикации выполняются public verification и обычная
   передача предыдущей публичной версии для ручного обновления владельцем.

В ходе аудита версия, release ID, теги, Git-история, публичные assets, установленные приложения,
пользовательские данные и секреты не менялись. В read-only части создан этот отчёт. Последующие source fixes принадлежат отдельно указанной
работе агентов. Вместе с этим обновлением отчёта уточнено описание барьера в ARCHITECTURE.

## Дополнительные фоновые проверки модели

На текущем CountdownCore выполнено 12 000 детерминированно сгенерированных fixtures
с seed `0xC0A17D0A20261116`, включая конец года, обычный и високосный февраль.
4 948 переносов успешно выполнены, 7 052 отклонены по независимо рассчитанным условиям.
Для успеха проверены точные ожидаемые source/recipient/neighbor snapshots, UUID conservation,
предел 10, favorite и JSON round-trip. Для отказа весь входной snapshot сохраняется.
[Исходник прогона](readiness-fuzz.swift) и [результат](readiness-fuzz.log) позволяют проверить
эту отдельную модельную проверку. Она выполнялась без AppKit и без управления окнами.

Добавлены и пройдены детерминированные сценарии отмены до Store admission, отклонения
отложенного подтверждения отменённого draft, изменения даты/capacity/UUID получателя
после выбора и отказа записи при смене суток. Последний сценарий проверяет rollback,
обычное истечение source и отсутствие несохранённого дня-получателя.

[Снимок хэшей текущих исходников и проверок](readiness-source-sha256.json) относится
к post-hardening этапу, отдельно от исходного native/manual manifest.

с версией 1.22.0/44 и выключенным updater для обычной разработки. [Receipt кандидата](readiness-candidate.json)
содержит полный executable hash, фактический compiler SDK и linked compatibility.

зафиксированы после внесения обоих исправлений.

релизных инструментов. `build-for-testing` подтверждает сборку внешнего тестового пакета,

[Дополнительная ручная матрица](release-readiness-manual.md) содержит 16 ещё не выполненных

проверок готовность нового кандидата к окончательной приёмке не подтверждается.
