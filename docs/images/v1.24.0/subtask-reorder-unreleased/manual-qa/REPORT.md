# Countdown Manager · расширенная ручная проверка

В проверке использованы отдельные профили с демонстрационными событиями. QA работал через нативный интерфейс и сверял сохранённый порядок, отметки и идентификаторы подзадач по JSON.

| Сценарий | Исходное состояние и действие | Ожидание |
| --- | --- | --- | --- |
| A1 | Большое окно, два открытых и одно выполненное дело. Клик по галочке, тексту и свободной части строки, повтор | Каждое действие меняет ровно одну отметку и счётчик. Строка переходит в правильную группу |
| A2 | Та же последовательность в компактной панели | Одна запись на клик, корректный счётчик и группировка |
| A3 | Событие с одной строкой и событие с пустым списком | У одиночной строки корректны обе отметки. В пустом списке отсутствует фиктивный прогресс. У одиночной строки drag недоступен |
| A4 | Tab до видимого фокуса, затем Space. Системное действие перестановки проверяется отдельно | Галочка работает с нативной клавиатуры, действия перемещения доступны внутри групп |
| B1 | Обе поверхности, верх/низ и середина, выполненные и открытые, длинная строка, максимум десять строк | Узкая подложка остаётся внутри колонки и группы. Текст и статусы сохраняются. Соседи освобождают место |
| B2 | Drag за пределы группы и повторная попытка. Клики после принятого и отменённого drag. Смена поверхности и перезапуск | Отмена сохраняет исходный порядок. Удачный drag сохраняет общий для поверхностей порядок, галочки остаются доступны |
| C1 | Открыть стрелкой существующего единственного получателя на завтра. Отменить. Повторно открыть и подтвердить | Начальный день завтра. Стрелка открывает inline выбор, Cancel сохраняет JSON. Подтверждение переносит один UUID с текстом в конец получателя. Соседи сохраняются |
| C2 | Два получателя на день, получатель с 10 строками, свободная дата, последнее дело источника | Несколько получателей требуют явного выбора. Переполненный заблокирован. Свободная дата создаёт обычный день. Исходное событие остаётся |
| C3 | При inline форме выбрать соседнее событие в desktop. В mini скрыть и вернуть. Отменить и проверить следующее действие | Desktop освобождает форму при смене события. Mini помнит открытый выбор. После отмены доступны галочки и перестановка |
| D1 | Сделать копию из каждой поверхности, сначала отменить, потом сохранить | Новый ID события и ID задач. Сохранённый порядок и текст унаследованы, все скопированные дела открыты. Исходный объект сохраняется. Отмена не создаёт записи |
| D2 | Copy → reorder → transfer и transfer → copy → reorder. Редактирование после цепочки | Пооперационная идентичность, порядок и статусы, отсутствуют побочные изменения исходника/результата |
| E1 | Поиск перемещённой задачи, свернуть/раскрыть чек-лист, коллекция/лента, темы | Поиск показывает текущего владельца. Смена представления сохраняет данные и нативную композицию |

## Результаты покейсно

Две проверенные изолированные сборки используют отдельные демонстрационные базы.

- Исходная `Countdown Deep QA.app`, SHA-256 `602363e0bcab84d2ae282d8df27b775cbc7f48b4ac258b603558c546409afb61`.
- Исправленная `Countdown Fixed QA.app`, SHA-256 `9d05e34808ada8efc3b94d97afd4b97afab6cc2ae47f024ed34072137b0ce5ad`.

| Строка матрицы | Результат и наблюдение |
| --- | --- |
| A1 | **Дефект до исправления, исправление подтверждено.** Обычные клики по единственной выполненной отметке и тексту сохранили 1/3. В той же исходной сборке соседний пункт при двух открытых строках переключился, а после этого единственный открытый стал недоступен. В исправленной сборке тот же клик по отметке дал 0/3, а обратный по тексту 1/3. Сохранились идентификаторы и порядок, подтверждены AX, файл и кадр. Отдельное испытание свободной части строки не проводилось. |
| A2 | **Дефект до исправления, исправление подтверждено.** В исходной мини-панели клик по чекбоксу и тексту единственной выполненной строки сохранил 1/3. В исправленной клик по тому же чекбоксу дал 0/3, клик по тексту вернул 1/3. После удачной перестановки и отменённого следующего drag галочка снималась. |
| A3 | **Основной сценарий прошёл.** Единственная задача в desktop переключилась 1/1 → 0/1 → 1/1. В mini единственная задача переключилась 1/1 → 0/1, в сохранённом профиле значение false. У desktop без задач показано сообщение «У этого события пока нет подзадач» без фиктивного 0/0. |

У события с 10 делами последняя открытая перенесена первой, число, все UUID и статусы сохранились. В mini перенос открытой строки в пределах группы сохранил оба UUID, порядок между ними и 1/3. Пофазное движение соседей до отпускания в ручном прогоне не измерялось. |

В исходной mini при открытой форме галочки disabled, выбор полного получателя блокировал кнопку, Cancel оставил файл байт-в-байт прежним. В исправленной mini подтверждение перевело один точный объект с прежним UUID в конец выбранного получателя, остальные строки источника и ранее сделанная копия остались прежними. Save из получателя создал копию с тремя открытыми задачами в сохранённом порядке, независимыми UUID и неизменённым получателем. |

Получатель сохранил своих предшественников и получил точный task UUID и текст в конец. Исходное скопированное событие и заполненный альтернативный получатель остались прежними. Снимки в каталоге [evidence](evidence/) показывают исходную неподвижную отметку в обоих окнах, исправленный прогресс, блокировку полного получателя, результат группового drag, черновик копии, пустую дату и владельца по поиску. Все мутации в этой проверке затрагивали только демонстрационные события. Исходный процесс QA закрыт. Системная раскладка и настройки не менялись. Исправленный тестовый процесс завершён после передачи управления для нативных сценариев.

## Дополнительный прогон удаления

На сборке с общим порядком карточки и редактора прошли [нативные проверки удаления](deletion-and-stress.txt).
Ряд сценариев удаляет редактируемую строку, продолжает ввод в соседних полях и проверяет
результат после отмены, сохранения и повторного открытия. Проверка удаления события оценивает
смену выделения при открытом подтверждении, двойную доставку, очередь за сохранением
галочки, откат при ошибке записи и удаление последнего события.

Отдельный прогон модели проверил 24 воспроизводимые последовательности по 256 выборов
действия. Он после каждой выполненной операции сравнивал список событий, владельцев,
порядок и состояния подзадач с ожидаемым снимком, включая отказы переноса и перестановки
уже удалённой строки. Сохранение и повторная загрузка прошли 692 раза. Этот прогон проверяет
данные и запись, проверка нативных элементов приведена отдельно.

Комбинированный нативный сценарий прошёл 3/3 на сборке с дополнительным тестовым
маршрутом. Он переставляет задачу, переносит её к единственному получателю,
копирует получателя на ту же дату под тем же названием, переставляет и удаляет
строку в копии, затем отменяет и подтверждает удаление всей копии. После
повторной загрузки исходные события и перенесённая задача сохранены.
Перетаскивание и открытие подтверждения удаления используют события AppKit,
остальные действия вызывают обработчики нативных элементов.
