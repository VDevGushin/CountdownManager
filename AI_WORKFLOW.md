# Работа над проектом с ИИ

## Роли

Владелец проекта выступает менеджером продукта: формулирует проблему, желаемое поведение, приоритет и ограничения. Писать код, выбирать Swift API или составлять техническое задание ему не требуется.

ИИ выступает ответственным разработчиком и самостоятельно:

1. Изучает текущий код и воспроизводит проблему.
2. Предлагает решение на уровне продукта, если есть заметные компромиссы.
3. Выбирает архитектуру и реализует изменение.
4. Добавляет или обновляет проверки.
5. Собирает приложение и проверяет затронутые сценарии.
6. Обновляет README, `AGENTS.md` и `VERIFICATION.md`, когда меняется поведение или процесс сопровождения.
7. Чётко сообщает, что готово, что проверено и какие ограничения остались.

## Как ставить задачи

Достаточно написать обычным языком, например:

- «Хочу уведомление за неделю и за день до события».
- «После добавления события приложение зависло».
- «Сделай интерфейс компактнее».

ИИ должен сам превратить такой запрос в техническую работу. Уточняющий вопрос нужен только тогда, когда ответ действительно изменит продуктовый результат.

## Обязательные правила разработки

- Не изменять и не удалять пользовательский `countdowns.json` во время тестов.
- Не записывать названия событий и emoji в диагностический журнал.
- Не выполнять файловые операции хранилища на главном UI-потоке.
- Сохранять совместимость с macOS 13+, если отдельно не согласовано иное.
- Не добавлять сторонние зависимости без явной пользы и объяснения.
- Не считать ручную проверку заменой автоматическим тестам для логики ядра.
- Перед установкой проверять сборку и подпись; установленную рабочую версию сохранять до завершения проверки новой.

## Definition of Done

Задача завершена, когда:

- пользовательский сценарий реализован;
- ошибки обрабатываются без потери данных;
- релевантные CoreChecks проходят;
- приложение успешно собирается;
- интерфейс проверен для пользовательских изменений;
- документация соответствует фактическому поведению;
- при запросе на установку или публикацию проверен именно установленный или опубликованный результат.

## Выпуск версии

Для пользовательского релиза ИИ обновляет версию в `Resources/Info.plist`, собирает `.app`, проверяет подпись, сохраняет предыдущую установленную копию, устанавливает новую и проверяет запуск на существующих данных. Публикация GitHub Release — отдельное внешнее действие и выполняется только по запросу владельца.
